# Shadow Intel audit and implementation

## Design source and preservation

`design.md` is a byte-for-byte copy of the supplied `DESIGN-x.ai.md`. Design direction: preserve the investigation workspace, apply xAI-inspired neutral surfaces and regular-weight typography. The design-taste-frontend skill is the sole design workflow; no Sites skills were used.

Dials: DESIGN_VARIANCE 4, MOTION_INTENSITY 3, VISUAL_DENSITY 6. This is a dense product workspace, outside the skill's marketing block scope. Hero, photography, testimonial, bento, and marketing-section checks do not apply. No promotional sections or decorative imagery were inserted.

Existing architecture: six React routes, sidebar, sticky topbar, overview pipeline, Cytoscape explorer, entity/search tables, alert cards, document analysis, and upload/settings. All route slugs, primary navigation labels, brand mark, section order, and graph layout choices remain. Existing graph motion is retained with a reduced-motion fallback. The original legacy dashboard files remain untouched.

Baseline tokens were blue-grey dark surfaces, warm paper light surfaces, system sans, green primary actions, and compact 3-4px corners. The reference is applied as near-black/charcoal surfaces, white primary and outlined pill actions, self-hosted Geist and Geist Mono, 8px cards/inputs, regular-weight headings, and no ornamental shadows. The existing manual light theme is preserved with equivalent neutral colors; the brand default stays dark. Semantic graph and severity colors remain meaningful rather than becoming decorative accents. Muted text and input outlines are adjusted for contrast.

SEO baseline is a client-rendered application with a document title, no per-route metadata, structured data or social cards. No route migration was performed.

## Repairs

- Upload mappings selected by the analyst are submitted to, validated by, and used by both server preview and load.
- Native `src`/`dst` JSON and CSV columns are detected correctly. CSV handles multiline quoted fields, escaped quotes, BOM, and duplicate/empty headers.
- Invalid JSON shapes, corrupt workbooks, nonexistent worksheets, oversize files, and unsupported relationships return readable validation errors.
- Switching files clears obsolete previews and mappings; asynchronous parsing cannot overwrite a newer selection. Changing a mapping invalidates confirmation until the analyst previews again.
- Legacy XLS worksheets are converted to CSV in the browser before server submission. Direct XLS API uploads return a conversion instruction.
- Dates, timestamps, and amounts survive ingestion. Financial records are not collapsed into a single payment, preserving evidence for pattern analysis. Non-finite frequencies do not crash ingestion.
- Person-to-vehicle/location edges no longer create a vehicle/location node for the person. Neo4j edge updates include the destination ID, avoiding updates to unrelated outgoing edges.
- Graph filters include relationship types actually present in the data. Ego reset restores the full graph. Path highlighting includes edges and clears stale dimming. Explicit demo mode supports local paths, ego focus, and dossiers.
- Graph requests ignore obsolete responses. Resize observation keeps the graph sized correctly; theme changes update labels and path highlights.
- Search ignores obsolete responses. Dossiers clear previous entity details and use keyed fragments. Entity detail close and neighbour controls navigate correctly.
- Document Intel supports text-file input and entity mentions link to search. Dossier alert links apply an entity filter.
- Connection testing authenticates against stats rather than testing only public health. API keys are masked. Requests have timeouts and malformed saved config is ignored.
- Failed overview requests terminate loading states. Demo availability is described accurately instead of claiming every page works offline.
- Mobile grid sizing prevents horizontal page overflow. Focus rings, a skip link, input labels, button contrast, and reduced-motion behavior are retained or improved.
- Graph and spreadsheet modules load by route, keeping the initial JavaScript bundle around 191 KB (61.5 KB gzip). Fonts are self-hosted. Direct development-server navigation to entity/document routes no longer hits API proxies.

## Verification

- `python -m pytest -q`: 17 passing tests. Tested with Python 3.12 in a temporary environment; FastAPI 0.141.1, NetworkX 3.6.1, scikit-learn 1.9.0, openpyxl 3.1.5. The environment used pandas 3.0.5 and uvicorn 0.52.4 rather than the repository pins. Two dependency deprecation warnings remain.
- `cd frontend && npm test`: CSV parsing, JSON-compatible column mapping, financial evidence preservation, and demo graph traversal checks pass.
- `cd frontend && npm run build`: TypeScript and optimized Vite production build pass. Vite reports a remaining 539 KB graph route chunk warning; this chunk is lazy-loaded.
- Browser checks with isolated headless Chrome: all six routes, live graph, demo paths/dossier/ego/reset, authenticated connection test, custom-column server preview, invalid-file reset. No page errors observed in the checked flows.
- All six routes fit a 390px viewport in both light and dark themes. Desktop checked at 1440px. Reduced-motion mode was exercised. Graph screenshots were visually reviewed.
- Lighthouse on the local production Overview page: performance 98, accessibility 100; FCP 1.5s, LCP 2.1s, total blocking time 0ms, CLS 0.026. This is a laboratory snapshot of one route, not a site-wide production or INP guarantee. The run had no saved API credentials. A visible-label/accessibility-name advisory was corrected afterward.
- `git diff --check` passes; the copied reference matches its source exactly.

## Limits

This is an evidence-driven repair pass, not a claim that every possible bug is eliminated. No production deployment was performed. Neo4j query scoping is covered with a mocked driver; a live Neo4j instance was not available. Optional NLP models were not installed or exercised end-to-end. Node-only JSON graph loading, watchlists, report generation, and broader roadmap items remain separate work. Existing backend authorization and evidence workflow are preserved.
